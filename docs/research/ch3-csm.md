Один такт таймеров, LFO и огибающих это один семпл YM: 24 слота × 6 тактов M (Nuked, README: «1 internal clock (6 master clocks)», 24 слота в `OPN2_Clock`); в BlastEm `clock_inc = 7 × 6 = 42` мастер-такта на слот (`ym2612.c:144`, `genesis.c:31`), `ym_run_timers` раз на 24 слота (`ym2612.c:517-520`), 24 × 42 = 1008 мастер-тактов. [И + Р]

Занятость YM после записи данных: 32 внутренних такта = 32 × 6 / M = **25,0 мкс** (Nuked `ym3438.c:232-235`, BlastEm `BUSY_CYCLES 32`, `ym2612.c:23,145,688,1040`). SGDK `YM2612_writeReg` ждёт снятия busy перед каждой записью (`/sgdk/src/ym2612.c`, `while (*pb < 0)`). Значит, две записи ROM подряд разделены не меньше чем 25 мкс, это больше одного семпла (18,8 мкс). [И + Р]

## Этап 21

### 1. Биты 0x28 и частоты канала 3 по операторам

Утверждение architect: S1-S4 это биты 4-7; A9/AD это S1, AA/AE S2, A8/AC S3, A6/A2 S4. **Подтверждено тремя независимыми источниками.**

- Nuked: `mode_kon_operator[i] = bit (4+i)` (`ym3438.c:408-412`); `[0]` → OP1, `[1]` → OP2, `[2]` → OP3, `[3]` → OP4 (`ym3438.c:1173-1183`). Частоты в спецрежиме: OP1 из `fnum_3ch[1]` (A9/AD), OP3 из `fnum_3ch[0]` (A8/AC), OP2 из `fnum_3ch[2]` (AA/AE), OP4 из частоты канала A2/A6 (`ym3438.c:1299-1320`). [И]
- BlastEm: операторы хранятся в порядке регистров, `op = 4*(reg&3) + (reg&0xC)/4` (`ym2612.c:812`), то есть индекс 0 = S1 (0x30), 1 = S3 (0x34), 2 = S2 (0x38), 3 = S4 (0x3C). `keyon_bits = {0x10, 0x40, 0x20, 0x80}` (`ym2612.c:205`) даёт S1 бит 4, S3 бит 6, S2 бит 5, S4 бит 7. Частоты: `index = op - 8; if (index < 2) index ^= 1` (`ym2612.c:610-616`), S1 → `ch3_supp[1]` (A9), S3 → `ch3_supp[0]` (A8), S2 → `ch3_supp[2]` (AA), S4 → частота канала. [И]
- plutiedev: биты 7-4 0x28 это S4-S1; таблица S1 $AD/$A9, S2 $AE/$AA, S3 $AC/$A8, S4 $A6/$A2. [И]
- ROM: номер оператора MDMI k = 0-3 это S1-S4: `reg_operator_index` меняет местами 1 и 2 (`synth.c:291-299`), то есть k=1 пишет 0x38 (S2), k=2 пишет 0x34 (S3). `synth_special_mode_pitch` пишет k=0 в A9/AD, k=1 в AA/AE, k=2 в A8/AC (`offset = (op+1) % 3`, `synth.c:443-448`). Значит, бит оператора k это `0x10 << k`, как пишет architect. [И + Р]
- Запись канала 3 в 0x28: младшие биты 2 (`synth.c:307-310`, Nuked `ym3438.c:420`, BlastEm `ym2612.c:771-776`). Байт `маска << 4 | 2`. [И]

### 2. Запись 0x28 с частью маски

**Подтверждено.** Оператор, чей бит не изменился, продолжает огибающую без новой атаки.

- Nuked: каждая запись 0x28 переписывает все четыре `mode_kon` канала (`ym3438.c:1173-1183`), но атака и сброс фазы бывают только на фронте: `kon_event = nkon && !okon`, `pg_reset = nkon && !okon`, отпускание `okon && !nkon` (`ym3438.c:606-612`), отдельно для каждого слота. [И]
- BlastEm: `changes = value ^ keyon`, `keyon()`/`keyoff()` только для изменившихся битов (`ym2612.c:776-795`). [И]
- Новая запись 0x28 применяется в слоте своего канала в течение одного семпла (Nuked `ym3438.c:1173`). Две записи 0x28 подряд разделены busy (25 мкс > 18,8 мкс), поэтому вторая не затирает первую до применения. [И + Р]
- На приставке: Nuked снят с YM3438, поведение по фронту на железе ожидаемо то же; ухом не проверено. [В, Ж]

### 3. Сброс LFO через 0x22

**Что делает выключение бита 3.**

- BlastEm: запись 0x22 без бита 3 сразу обнуляет `lfo_counter` (`ym2612.c:722-725`); шаги `lfo_am_step` и `lfo_pm_step` обнуляются только на ближайшем такте таймеров (`ym2612.c:275-277`). После включения счёт идёт с нуля, первый шаг ровно через `lfo_timer_values[f] + 1` тактов (`ym2612.c:266-274`). Фаза после включения детерминирована с точностью до одного такта (18,8 мкс). [И + Р]
- Nuked (кристалл): `lfo_cnt &= lfo_en` на каждом внутреннем такте (`ym3438.c:836-848`, вызов `ym3438.c:1334`), то есть счётчик шага LFO (7 бит) держится в нуле, пока LFO выключен. **Но предделитель `lfo_quotient` не обнуляется и продолжает считать** (`ym3438.c:838-845`: его сбрасывает только достижение периода, бит включения на него не влияет). [И]
- Следствие для железа [Р + В]: после включения первый шаг приходит через случайные 1…(c+1) семплов, где c+1 это период предделителя. Разброс начала вибрато между нотами до одного шага LFO из 128:

| f (0x22 биты 0-2) | c+1, семплов | Частота LFO NTSC, Гц | Наибольший сдвиг начала, мс |
|---|---|---|---|
| 0 | 109 | 3,82 | 2,05 |
| 1 | 78 | 5,34 | 1,46 |
| 2 | 72 | 5,78 | 1,35 |
| 3 | 68 | 6,12 | 1,28 |
| 4 | 63 | 6,61 | 1,18 |
| 5 | 45 | 9,25 | 0,84 |
| 6 | 9 | 46,2 | 0,17 |
| 7 | 6 | 69,4 | 0,11 |

(53267 / (128 × (c+1)); c из `lfo_cycles`, `ym3438.c:182-184`, то же в BlastEm `ym2612.c:42`; частоты совпадают с plutiedev 3,82…69,22 Гц.) Высота у PM меняется раз в 4 шага счётчика (`lfo_pm = lfo_cnt >> 2`, `ym3438.c:1233`), поэтому у двух нот кривые вибрато одинаковы по форме и сдвинуты по времени не больше чем на один шаг из 128. В BlastEm такого разброса нет. **На приставке «одинаковое начало вибрато» значит «до 1/128 периода LFO», а не точно.** [Р + В]

**Сколько держать выключенным.**

- BlastEm: нужен хотя бы один такт таймеров между двумя записями, иначе `lfo_counter` обнулится, а шаги нет (обнуляются они только на такте при `lfo_enable == 0`). Достаточно промежутка больше 18,77 мкс. [И + Р]
- Nuked: достаточно одного внутреннего такта (0,78 мкс) для `lfo_cnt = 0`; `lfo_am`/`lfo_pm` пересчитываются из него в слоте 0 каждого семпла (`ym3438.c:1231-1243`). [И + Р]
- **40 мкс хватает в обоих (2,13 такта).** Но это больше нужного: условие «≥ 1 такт», а две записи подряд уже разделены busy 25 мкс > 18,77 мкс. Отдельная пауза поверх busy в BlastEm, по коду, не нужна. Это и решает опыт этапа «две записи подряд против 40 мкс». [Р + В] Утверждение architect «40 мкс это два такта» верно арифметически, «нужно два» по коду не следует, нужен один.
- Фаза после включения в обоих: счётчик 0, AM в наибольшем ослаблении, PM 0 (ниже). [И]

### 4. Что сброс делает с другими каналами

LFO у чипа один, сброс действует на все каналы с AMS или PMS. [И: одна пара `lfo_am`/`lfo_pm` на чип, `ym3438.c:1233-1242`, `ym2612.c:266-277`]

- AM: на шаге 0 ослабление наибольшее. Nuked: `lfo_cnt = 0` → `lfo_am = (0 ^ 0x3F) << 1 = 126` (`ym3438.c:1234-1242`); BlastEm то же (`~0 & 0x7E = 126`, `ym2612.c:405`). [И] Величина по AMS (Nuked `eg_am_shift = {7, 3, 1, 0}`, `ym3438.c:127-129`, единица огибающей ≈ 0,094 дБ): AMS 0 → 0; AMS 1 → 15 ед. ≈ 1,4 дБ; AMS 2 → 63 ед. ≈ 5,9 дБ; AMS 3 → 126 ед. ≈ 11,8 дБ. [И + Р] Сброс при произвольной фазе даёт мгновенный скачок громкости до 11,8 дБ у операторов с битом AM всех каналов. Скачок огибающей без перехода это щелчок; насколько слышен, зависит от звука. [В, Ж]
- PM: на шаге 0 смещения нет (`lfo_pm = 0`). Высота всех каналов с PMS прыгает к основной на величину текущего отклонения, до полной глубины PMS (таблицы `pg_lfo_sh1/sh2`, `ym3438.c:134-156`; часто приводят ±80 центов для PMS 7, это я в источнике не проверял, [В]). Фаза генератора при этом непрерывна, щелчка от PM нет, есть рывок высоты. [И + В]
- Пока LFO выключен (25-40 мкс, 1-2 семпла), AM стоит в наибольшем ослаблении и PM в нуле: часть скачка выше. [И + Р]

### 5. Защёлка старшего байта AC-AE

- Nuked: у AC-AE **одна защёлка `reg_ac` на чип**, отдельная от `reg_a4` (`ym3438.c:304-317`). Запись A8/A9/AA берёт старший байт из `reg_ac`, то есть из последней записи в любой из AC/AD/AE. [И]
- BlastEm: у каждого из трёх свой `block_fnum_latch` (`ym2612.c:876-891`), у A4-A6 свои по каналам (`ym2612.c:863-875`). [И]
- Правило, верное для обоих: пара AC→A8 (AD→A9, AE→AA) подряд, без записи в другой AC-AE между ними; старший байт первым, частота меняется на записи младшего. Запись A4-A6 между ними безвредна (у Nuked другая защёлка). То же правило для A4-A6: между A4 и A0 не писать другой A4-A6 (факт этапа 20, `docs/research/arpeggio.md:79-80`). [И + В]
- ROM сегодня так и пишет: `synth_special_mode_pitch` MSB, затем LSB того же оператора (`synth.c:443-448`). При DAC вкл между записями `release_z80_bus` пишет адрес 0x2A (`synth.c:500-504`), а PCM4 пишет данные DAC; ни то ни другое защёлку не трогает (Nuked меняет `reg_ac` только записью 0xAC-0xAE). [И + В]

### 6. Чип в MK-1631 (модель 2)

- Модель 2 VA0-VA1.8 и VA3: ASIC FC1004 с ядром YM3438 («modified YM3438» по consolemods); VA2, VA2.3: дискретный YM2612; VA4: FJ3002 (315-5960), YM3438 внутри. Источники: https://consolemods.org/wiki/Genesis:ASIC_Information, https://segaretro.org/Mega_Drive_PCB_revisions, комментарий Nuked `ym3438.h:38-39` («YM2612 emulation (MD1, MD2 VA2)»). Ревизию конкретной приставки владельца я не знаю. [И по источникам, ревизия Ж]
- В Nuked тип чипа меняет только выход ЦАП (лестница) и чтение статуса (`ym3438.c:985, 1383, 1413`); канал 3, LFO, таймеры и CSM для YM2612 и YM3438 один код. [И] Отличий в канале 3 и LFO между YM2612, YM3438 и ASIC я в источниках не нашёл. Сравнения на кристалле YM2612 в Nuked нет, только YM3438. [В, Ж]

## Этап 22

### 1. Биты режима 0x27

- 00 обычный, 01 частоты по операторам, 10 CSM, **11 частоты по операторам без CSM**.
  - Nuked: `mode_ch3 = bits 7-6`, `mode_csm = (mode_ch3 == 2)` (`ym3438.c:399-400`); выбор частот по операторам при любом ненулевом `mode_ch3` (`ym3438.c:1299`). [И]
  - BlastEm: `ch3_mode = value & 0xC0` (`ym2612.c:761`), частоты по операторам при ненулевом (`ym2612.c:610`), CSM только при `== 0x80` (`ym2612.c:202, 234`). [И]
  - plutiedev перечисляет 00, 01, 10, про 11 молчит. [И] Значит, 11 по обоим эмуляторам ведёт себя как 01; ROM его не пишет, и это ничего не закрывает. [В]
- **В режиме 10 частоты тоже по операторам** (оба эмулятора, те же строки). Форманты через A8-AE работают в CSM. [И]
- Прочие биты (Nuked `ym3438.c:401-407`, BlastEm `ym2612.c:26-33, 740-756`): бит 0 запуск таймера A, бит 1 запуск B, бит 2 флаг A при переполнении, бит 3 флаг B, бит 4 сброс флага A, бит 5 сброс флага B. Биты 4-5 действуют один раз и не хранятся. Схема architect (7-6 и 0 ведёт ROM, 1-3 из тени, 4-5 не хранить) с этим сходится. [И]

### 2. Частота и период таймера A

- Такт таймера A один раз в семпл, M / 144: **53267,04 Гц NTSC, 52781,15 Гц PAL** (53203395 / 1008 по BlastEm; при 53203424 выходит 52781,17). [И + Р]
  - Nuked: прибавка на `cycles == 1`, раз в 24 внутренних такта (`ym3438.c:1097-1100`). [И]
  - BlastEm: `ym_run_timers` раз на 24 слота (`ym2612.c:517-520`). [И]
- **Период ровно 1024 − NA тактов в обоих.** [И + Р]
  - BlastEm: после перезагрузки счётчик равен NA, растёт до 1023 (`TIMER_A_MAX`, `ym2612.c:91`) за 1023 − NA тактов, на следующем такте перезагрузка (`ym2612.c:221-233`): 1024 − NA.
  - Nuked: счёт 10 бит, переполнение на 1024 (`time >> 10`, `ym3438.c:1111`), перезагрузка из `timer_a_reg` через 2 внутренних такта после переполнения, раньше следующей прибавки (`ym3438.c:1070-1095`): 1024 − NA прибавок.
  - Документация: plutiedev «($400 − TMRA) × 18.77µs»; шпаргалка Sega «18 × (1024 − NA) мкс» это округление 18,77. [И]
- Формула ROM `NA = 1024 − round(53267 / f)` верна. Нижняя граница: NA 0 даёт 53267 / 1024 = **52,02 Гц**. Это +3,5 цента к G#1 (нота 32, 51,91 Гц). Значит, нота 32 при NA 0 точна, «самая низкая точная нота» это 32, не 33. Зажим ниже 32 даёт ошибку 104 цента на ноте 31 и дальше по 100 на ноту. Тест «ноты ниже 33 дают NA 0» с этим не спорит. [Р]
- Точность (NTSC, NA = 1024 − round(53267 / f)) [Р]:

### 3. Когда действует новое 0x24/0x25 и порядок записей

- В обоих эмуляторах 0x24 и 0x25 пишут прямо в регистр перезагрузки, без защёлки (Nuked `ym3438.c:387-393`, BlastEm `ym2612.c:729-736`). Идущий счёт не меняется: новое значение берётся **на следующей перезагрузке** (Nuked `ym3438.c:1087-1090`, BlastEm `ym2612.c:233`) или при запуске битом 0. [И]
- Значит, изменение высоты под нотой вступает со следующего периода, задержка до одного старого периода (до 19,2 мс при NA 0, 2,3 мс на A4). [Р]
- Промежуточное значение. Если перезагрузка попала между записями 0x24 и 0x25, один период идёт со смешанным NA (старшие 8 бит новые, младшие 2 старые или наоборот), ошибка до 3 тактов на один период. Промежуток между записями не меньше busy 25 мкс, с обвязкой ROM около 30 мкс (оценка). [Р + В]
  - Нота 69: период 121 семпл = 2,27 мс; вероятность попадания ~30 / 2270 ≈ 1,3%; ошибка до 3 / 121, ~43 цента на 2,3 мс.
  - Нота 96: период 25 семплов = 0,47 мс; вероятность ~6%; ошибка до 3 / 25, ~200 центов на 0,47 мс.
  - Это одна неверная пачка, не сдвиг высоты; слышно ли, решит ухо. [В, Ж]
  - В эмуляторах порядок 0x24/0x25 не важен: риск один и тот же. Совет «сначала старший» встречается в пересказах руководства Sega, сам текст я не открыл (плохо проверено). На устройство таймера на кристалле (Nuked) порядок не влияет. [В]
  - Риск снимает только запись одного регистра, когда меняются только его биты. Это выбор реализации, не условие железа. [В]

### 4. Ключ CSM

- **Нажатие на переполнении, отпускание через один семпл, в обоих.** [И]
  - BlastEm: на переполнении `csm_keyon = 0xF0`, `keyon` четырёх операторов, кроме уже нажатых через 0x28 (`ym2612.c:234-243`). На следующем такте при идущем таймере `csm_keyoff` (`ym2612.c:222-226`).
  - Nuked: `mode_kon_csm = load` на `cycles == 2` (`ym3438.c:1072-1084`), где `load` это флаг переполнения (или запуск). Через 24 такта флаг уже 0, ключ снимается. CSM даёт `eg_kon_latch = 1` на один семпл (`ym3438.c:1165-1172`).
- Следствие для звука [И + В]: ключ CSM держится один семпл, сразу за атакой идёт отпускание с RR. При AR ниже 31 атака почти не успевает, звук тихий; D1R, D2R и SL почти не важны. Форманту формирует RR. В README полезно написать, что в CSM нужен AR 31, а затухание задаёт RR.
- **Остановка таймера сразу после переполнения:**
  - BlastEm: `ym_run_timers` при снятом бите 0 таймер A не обрабатывает вовсе (`ym2612.c:221`), `csm_keyon` остаётся 0xF0, операторы висят нажатыми. Запись 0x28 = 0x02 их тоже не отпустит: для канала 3 изменения считаются как `(value | csm_keyon) ^ (keyon | csm_keyon)` (`ym2612.c:776-778`). Снимают их смена режима (`ym2612.c:757-759`) или следующий запуск таймера. [И]
  - Nuked: ключ снимается через один семпл независимо от таймера, зависания нет. [И]
  - Вывод architect «Note Off через смену режима» верен и нужен для BlastEm. [И + В]
- **Смена режима 10 → 01 снимает ключ:** BlastEm да (`ym2612.c:757-759`, при любом переходе из 10 в не-10); Nuked `mode_kon_csm = 0` на ближайшем `cycles == 2` (`ym3438.c:1076-1084`). [И]
- **Нюанс Nuked, которого нет в BlastEm.** В режиме CSM TL канала 3 вносится в уровень огибающей при нажатии CSM (`nextlevel |= eg_tl << 3`, `ym3438.c:696-699`) и не прибавляется на выходе (`ym3438.c:824-828`). В BlastEm TL прибавляется на выходе всегда (`ym2612.c:403`). Мой вывод: при AR 31 громкость начала та же, но огибающая стартует уже с ослабления TL, поэтому у оператора с большим TL затухание до порога (0x3F0) короче, чем в BlastEm. Оператор канала 3, нажатый через 0x28 в режиме CSM, на кристалле звучал бы без TL; ROM в CSM 0x28 не пишет, поэтому это не мешает. [И по коду, В по смыслу, Ж по звуку]

### 5. Ключ CSM вместе с ключом 0x28

- Складываются по ИЛИ в обоих: BlastEm `ym2612.c:776-778` и проверка `changes = 0xF0 ^ keyon` в `ym2612.c:209-216, 236-242`; Nuked `eg_kon_latch = mode_kon`, затем `= 1` при CSM (`ym3438.c:1165-1172`). [И]
- Если 0x28 держит оператор нажатым, переполнение не даёт фронта и атаки нет, повторов не слышно. Решение architect «в CSM не писать 0x28 канала 3» верно. [И + В]

### 6. Первое переполнение после запуска битом 0

- **Сразу, в обоих, и в CSM это сразу нажатие.** Период 1024 − NA идёт уже после него. [И]
  - BlastEm: фронт бита 0 ставит `timer_a = MAX` и `BIT_TIMERA_LOAD` (`ym2612.c:741-743`). На ближайшем такте ветка переполнения: перезагрузка NA, флаг статуса не ставится, CSM нажимает (`ym2612.c:227-243`). Нажатие через 0…18,8 мкс после записи.
  - Nuked: фронт `timer_a_load` при `!timer_a_load_lock` даёт `load` на `cycles == 2` (`ym3438.c:1072-1075`), и `mode_kon_csm = load`: нажатие в ближайшем семпле.
- Повторная запись бита 0 = 1 при идущем таймере его **не перезапускает**: BlastEm проверяет `!(timer_control & ENABLE)` (`ym2612.c:741`), Nuked ловит фронт через `timer_a_load_lock` (`ym3438.c:1074-1075`). Чтобы новая нота CSM начала период заново, нужен 0, потом 1. Nuked снимает `lock` раз в семпл, поэтому между записями нужно не меньше одного семпла. Две записи подряд разделены busy 25 мкс, этого хватает. Сегодня Note Off пишет 0x40, и следующий Note On даёт фронт. Нота поверх звучащей (легато, нота стека) без промежуточного 0 оставит старую фазу таймера и сменит только NA со следующей перезагрузки. [И + Р + В]

### 7. `YM2612_reset`, драйверы NULL и PCM4

- `YM2612_reset` (`/sgdk/src/ym2612.c:22-~95`) пишет 0x22 = 0, **0x27 = 0**, 0x2B = 0, регистры операторов и частот только части 0 (каналы 1-3), B4-B6 части 0 = 0xC0, key off всех шести. **0x24, 0x25, 0x26 не пишет.** [И]
  - Следствие: после загрузки драйвера NA остаётся прежним, но таймер стоит, режим 00, LFO выключен. Ключ CSM в BlastEm снимается сменой режима 10 → 00 (`ym2612.c:757-759`). [И + В]
  - Попутно: `YM2612_reset` пишет A8 до AC (младший до старшего), это безвредно для нулей. [И]
- Кто вызывает `YM2612_reset`: `Z80_loadDriverInternal` (`/sgdk/src/z80_ctrl.c:253-273`) и `SND_NULL_loadDriver` (`/sgdk/src/snd/sound.c:19-35`). ROM грузит PCM4 при DAC вкл и NULL при DAC выкл (`synth.c:471-482`). Загрузка PCM4 сначала выгружает текущий драйвер через NULL (`z80_ctrl.c:225-250`), то есть `YM2612_reset` вызывается дважды. ROM пишет после этого только 0x2B (`write_dac_reg`). Плагин восстанавливает LFO и режим канала 3 через `patch_sync` (`docs/research/hardware-rom.md:510-517`). Замысел architect «после загрузки драйвера ROM сам пишет 0x27 из тени» нужен. [И + В]
- Драйвер NULL пишет в YM ничего (`/sgdk/src/snd/drv_null.s80`: только цикл и RETI). [И]
- PCM4 пишет только 0x2B = 0x80 и 0x2A = 0x80 (`initDAC`, `/sgdk/inc/snd/z80_fct.i80:10-15`, вызов `drv_pcm4.s80:477`), дальше только данные в порт 1 (`sampleOutput`, `drv_pcm4.s80:230-244`, HL' = YMPORT1, `drv_pcm4.s80:486`). Из YM он читает только бит 7 (busy) в `writeYM0`/`writeYM1` (`z80_fct.i80:26-53`). **Флаги таймеров (биты 0-1 статуса) PCM4 не читает и не сбрасывает.** [И]
- **Запись 0x24, 0x25, 0x27 с битом 0 при работающем PCM4 безопасна**, если идёт через `write_reg_safe`: шина Z80 захвачена на время записи, после неё ROM снова защёлкивает адрес 0x2A для драйвера (`synth.c:484-504`). Таймер A и флаг переполнения на работу PCM4 не влияют: драйвер считает такты сам и статус не читает. Флаг A ставится, только если в тени бит 2 (`ym2612.c:230`, `ym3438.c:1109`). Даже тогда бит 7 busy от флагов не зависит. [И + В]
- Вывод IRQ YM на Mega Drive никуда не подключён (общеизвестно, источника в коде проекта нет), поэтому флаги прерываний не дают. [В]

### 8. CSM на YM3438 и ASIC модели 2

- Nuked (кристалл YM3438) CSM моделирует, README: «SSG-EG, CSM mode emulation». Поведение описано выше: ключ на один семпл, ИЛИ с 0x28, нюанс TL. [И]
- Тип YM2612 в Nuked меняет только ЦАП и чтение статуса, CSM у обоих один код (`ym3438.c:985, 1383, 1413`). [И] Работает ли CSM на YM2612, YM3438 и FC1004/FJ3002 одинаково, проверяется только на приставке. Источника о различиях я не нашёл. [Ж]
- Нюанс TL в CSM (п. 4) есть на кристалле по Nuked и отсутствует в BlastEm. Звук CSM в BlastEm и на приставке может различаться затуханием операторов с большим TL. [В, Ж]

## Расхождения с решениями architect

1. **Сброс LFO на кристалле не полный** (этап 21). Nuked обнуляет счётчик шага, но не предделитель `lfo_quotient`, поэтому начало вибрато на приставке гуляет до одного шага из 128 (до 2,05 мс при f 0). В BlastEm сброс детерминирован. Тест 7 этапа 21 (±2 цента в BlastEm) это не задевает. «Одинаковое начало вибрато» на приставке выполнимо только с этой точностью. [И + Р + Ж]
2. **40 мкс не обязательны** (этап 21). Нужен один такт таймеров (> 18,77 мкс) между выключением и включением, а не два. Busy после первой записи уже даёт 25 мкс. 40 мкс работает, но лишнее; опыт этапа это покажет. [И + Р]
3. **Нижняя точная нота CSM 32, а не 33** (этап 22). NA 0 = 52,02 Гц, это G#1 +3,5 цента. Тесты architect от этого не ломаются. [Р]
4. **CSM требует AR 31, затухание задаёт RR**: ключ CSM держится один семпл. В решениях этого нет, это касается README и звуков по умолчанию, а не кода. [И + В]
5. **TL в CSM на кристалле ведёт себя иначе, чем в BlastEm** (Nuked `ym3438.c:696-699, 824-828`). Решения не ломает, проверка звука только на приставке. [И + Ж]
6. **Повторная запись бита 0 таймер не перезапускает**: нота CSM поверх звучащей без промежуточного 0x27 с битом 0 = 0 оставит старую фазу таймера. Это выбор поведения легато, не ошибка схемы. [И]

Сошлось с architect: биты 0x28 и карта частот операторов; часть маски без новой атаки; 11 это спецрежим без CSM; период 1024 − NA при M / 144, 53267 и 52781 Гц; новое NA со следующей перезагрузки; нажатие на переполнении и отпускание через такт; зависание в BlastEm при остановке только таймера; снятие ключа сменой режима; ИЛИ с ключом 0x28; первое нажатие сразу после запуска; `YM2612_reset` пишет 0x27 = 0 и не пишет 0x24-0x26; NULL и PCM4 0x24-0x27 не пишут и флагов не читают.

## Что решает только приставка [Ж]

- Слышен ли щелчок от скачка AM при сбросе LFO и насколько гуляет начало вибрато.
- Звук CSM на YM2612 против YM3438/ASIC, нюанс TL.
- Пропущенная или неверная пачка CSM при смене NA (смешанное значение 0x24/0x25).
- Ревизия чипа в приставке владельца (VA2/VA2.3 модели 2 с дискретным YM2612, остальные модели 2 с YM3438 в ASIC).
