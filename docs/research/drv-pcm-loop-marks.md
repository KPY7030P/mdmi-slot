# drv_pcm: метки петли и релиз без правки драйвера

Дата: 2026-11-10, hardware-specialist, для этапа 18b. Уточняет абзац фактов в ROADMAP (2026-11-09).

Метки: **[И]** подтверждено источником, **[Р]** посчитано, **[В]** мой вывод, **[Ж]** решается только на приставке.

Источники SGDK взяты из образа сборки ROM (`tools/docker/rom/Dockerfile`, `ghcr.io/rhargreaves/docker-sgdk:v2.00-mw-bs@sha256:82d2928c...`, `SGDK_VERSION 2.00`), командой `docker run --rm mdmi-rom-build cat /sgdk/...`:
`/sgdk/src/snd/pcm/drv_pcm.s80`, `/sgdk/src/snd/pcm/snd_pcm.c`, `/sgdk/inc/snd/z80_def.i80`, `/sgdk/inc/snd/z80_mac.i80`, `/sgdk/inc/z80_ctrl.h`, `/sgdk/src/z80_ctrl.c`, `/sgdk/src/snd/smp_null.s`.

## 1. Раскладка ОЗУ Z80

Адрес 68000 = 0xA00000 + адрес Z80 (`z80_ctrl.h:27,64-76`). Слова little-endian (`LD HL,(nn)`), 68000 пишет и читает Z80 RAM только байтами (`z80_ctrl.c:188-193`, `snd_pcm.c:92-100`).

| Z80 | 68000 | Имя | Содержимое | Источник |
|---|---|---|---|---|
| $0100 | A00100 | COMMAND | бит 0 PLAY (бит 4 STOP драйвер не читает) | `z80_def.i80:14-15,39`; `drv_pcm.s80:169,188` |
| $0102 | A00102 | STATUS | бит 0 PLAYING, бит 7 READY | `z80_def.i80:17-18,40` |
| $0103 | A00103 | STATUS+1 | бит 0 LOOP | `z80_mac.i80:295-300`; `snd_pcm.c:111-112` |
| $0104 | A00104 | WAVADR u16 | адрес сэмпла >> 8 (биты 8-23) | `drv_pcm.s80:38`; `snd_pcm.c:92-93` |
| $0106 | A00106 | WAVLEN u16 | длина >> 8, в блоках по 256 байт | `drv_pcm.s80:39`; `snd_pcm.c:95-96` |
| $0108 | A00108 | RATE | 0..5 | `drv_pcm.s80:40` |
| $010A | A0010A | PAN | значение B6 (0x40 R, 0x80 L, 0xC0 C) | `drv_pcm.s80:41`; `snd_pcm.c:100` |
| $0114 | A00114 | IWAVADR u16 | текущий блок | `drv_pcm.s80:43` |
| $0116 | A00116 | IWAVLEN u16 | осталось блоков в проходе | `drv_pcm.s80:44` |
| $0124 | A00124 | NULLWAVADR u16 | блок `smp_null` (256 нулей) | `drv_pcm.s80:46`; `snd_pcm.c:31-39`; `smp_null.s` |
| $0126 | A00126 | NULLWAVLEN u16 | 1 | `drv_pcm.s80:47` |

- Счётчики IWAVADR/IWAVLEN именно в блоках: `INC HL` / `DEC HL` раз за блок (`drv_pcm.s80:295-305`). [И]
- Сэмпл должен лежать ниже 0x400000: биты 22-23 банка драйвер пишет нулями (`drv_pcm.s80:267-268`). [И]
- `SND_PCM_startPlay` (`snd_pcm.c:77-115`): `Z80_requestBus(TRUE)` (пишет 0x100 в A11100 и A11200, ждёт сброса бита 8 в A11100, `z80_ctrl.c:69-87`), затем байты WAVADR lo/hi, WAVLEN lo/hi, RATE, PAN, `COMMAND |= 1`, `STATUS+1` бит 0 = loop, `Z80_releaseBus()` (0 в A11100, `z80_ctrl.c:114-120`). Порядок под одним захватом для Z80 не важен. STATUS бит 0 он не трогает. [И]

## 2. Цикл драйвера (один проход = один блок = 256 периодов сэмпла)

`main_loop` (`drv_pcm.s80:532-584`) идёт по слотам $00-$FF, слот = период сэмпла P:

- $00-$03 `handlePlayCommandWhilePlay4` (165-216): BIT COMMAND.0; если 1: RES COMMAND.0 (188), copyChannelParams WAVADR/WAVLEN → IWAVADR/IWAVLEN (193, макрос 107-114), SET STATUS.0 (197), чтение RATE и PAN (198-201), запись B6 (205-213).
- $04-$07 банк и SP из IWAVADR (229-281); $08-$87 чтение 256 байт блока в буфер записи (546-551).
- $88-$89 `updateChannelDataWhilePlay2` (291-307): IWAVADR+1, затем IWAVLEN−1 (чтение в HL, запись через один вывод сэмпла).
- $8A-$8D `checkChannelEndWhilePlay4` (317-372): если IWAVLEN = 0: LOOP=1 → снова copyChannelParams (346-353), LOOP=0 → IWAV = null, сброс PLAYING и LOOP (360-369).
- $FE-$FF смена буферов (579-583): блок, прочитанный в проходе i, звучит в проходе i+1. [И]

Тайминг [И по комментариям циклов, Р]: S = длина `sampleOutputAndWait` = 30 + W, P = 92 + W, W = 18/69/129/172/229/351 (`drv_pcm.s80:69-99`).

| RATE | P, такты Z80 | S | Гц NTSC (3579545/P) | Гц PAL (3546893/P) | блок, мс NTSC |
|---|---|---|---|---|---|
| 0 | 110 | 48 | 32541 | 32244 | 7,87 |
| 1 | 161 | 99 | 22233 | 22030 | 11,5 |
| 2 | 221 | 159 | 16197 | 16049 | 15,8 |
| 3 | 264 | 202 | 13559 | 13435 | 18,9 |
| 4 | 321 | 259 | 11151 | 11049 | 23,0 |
| 5 | 443 | 381 | 8080 | 8007 | 31,7 |

Частоты в ROADMAP (31,5 / 21,6 ...) ниже номинала: замер в BlastEm, где чтение банка стоит 3 такта Z80 (`genesis.c:1786-1787`), а драйвер закладывает 2 (`drv_pcm.s80:449`). [И/В]

Команда берётся раз в проход, на слоте $00, до чтения блока на $04: новая команда или повторная копия на $8A без шва. [И]

## 3. Старт со вступлением

Признак «драйвер скопировал параметры»: STATUS.0 ставится только в обработчике команды, после копии (`drv_pcm.s80:193,197`), и сбрасывается только при остановке (138, 369). Если 68000 при старте сам сбросит STATUS.0, то STATUS.0 = 1 значит, что копия уже сделана. Тогда запас 130 мкс не нужен. [И + В]
Старый признак (COMMAND.0 = 0) хуже: RES стоит до копии; окно от RES до конца копии S+68 тактов, 32 мкс на RATE 0 и 125 мкс на RATE 5 (это и есть те 130 мкс). [Р]

Срок перезаписи PARAMS: первая повторная копия идёт через (L−1)·256 + 138 слотов после установки PLAYING, где L = конец петли − начало в блоках (ограничение на L, а не на длину вступления). При опросе раз в кадр L должен быть не меньше [Р]:

| RATE | NTSC, опрос в кадр | NTSC, запас кадр | PAL, опрос в кадр | PAL, запас кадр |
|---|---|---|---|---|
| 0 | 3 | 5 | 4 (3 даёт запас 1 сэмпл) | 6 |
| 1 | 2 | 4 | 3 | 4 |
| 2 | 2 | 3 | 2 | 3 |
| 3 | 2 | 3 | 2 | 3 |
| 4 | 2 | 2 | 2 | 3 |
| 5 | 2 | 2 | 2 | 2 |

Кадр: NTSC 16,69 мс, PAL 20,12 мс (`genesis.c:27-39`). Вступление ≥ 1 блока, петля ≥ 1 блока, поэтому меньше 2 не бывает. В ROADMAP стоит «1-3 блока»: правильно 2-3 при опросе в кадр, до 6 с запасом в кадр на PAL. Обработчики кадра идут из главного цикла, не из прерывания (`scheduler.c:30-33,60-66`), поэтому опрос может опоздать на время обработки MIDI. Можно опрашивать в tick-обработчике (`scheduler.c:47-53`), пока ждём, и срок станет короче; сколько, не измерено. [В]

Если вступления нет (loop_start = start), перезапись не нужна.

## 4. Релиз на Note Off

Инвариант вне окна обновления: IWAVADR + IWAVLEN = блок конца текущего прохода (`drv_pcm.s80:295-305`). Поэтому IWAVLEN = end − IWAVADR продлевает текущий проход до конца релиза, а LOOP = 0 останавливает драйвер на конце (360-369). Во вступлении это даёт остаток вступления, петлю один раз и релиз. Если IWAVLEN = 0 (между $88 и $8A), запись тоже верна: проверка увидит ненулевую длину и пойдёт в релиз. [И + В]

Гонки [Р]:
- Окно обновления: от записи IWAVADR (слот $88 + S+38) до записи IWAVLEN (2S+84), около S+50 тактов на блок. Захват шины в этом окне даёт ошибку на блок или потерю записи: драйвер пишет поверх старое−1. Тогда петля доигрывает и молкнет без релиза. Вероятность на Note Off (S+50)/(256·P): 0,35% / 0,36% / 0,37% / 0,37% / 0,38% / 0,38% для RATE 0-5.
- Последний блок прохода: если захват попал между чтением IWAVLEN = 0 в проверке и чтением LOOP (около S+71 такта), драйвер уже идёт в остановку и ставит null. Вероятность около 0,4% / (длина петли в блоках).
- На настоящей Z80 BUSREQ принимается в конце M-цикла, то есть и между двумя байтами `LD (nn),HL`, и внутри `SET/RES (HL)`. Возможны рваные 16-битные значения (Zilog UM0080, https://www.zilog.com/docs/z80/um0080.pdf). Это укладывается в те же окна. [В, Ж]

Проверка и одна поправка: после записи отпустить шину и подождать, пока закончится вся критическая область (от записи IWAVADR до setNullWav, 4S+274 такта: 130 / 187 / 254 / 302 / 366 / 502 мкс для RATE 0-5; 600 мкс хватает на всех). Потом проверить снова. Следующее окно наступит не раньше чем через 120 слотов, поэтому одной поправки достаточно. Если драйвер уже остановился, новая команда на релиз подхватится на ближайшем $00 до чтения блока, без шва: до него не меньше 3,5 мс (RATE 0) и 14 мс (RATE 5). [Р]

## 5. Псевдокод (68000, вместо SND_PCM_startPlay/stopPlay для сэмплов с метками)

```c
#define Z_CMD    ((vu8*)0xA00100)   // bit0 PLAY
#define Z_STAT   ((vu8*)0xA00102)   // bit0 PLAYING, bit7 READY: change only with |= / &=
#define Z_LOOP   ((vu8*)0xA00103)   // bit0 LOOP
#define Z_WAVADR ((vu8*)0xA00104)
#define Z_WAVLEN ((vu8*)0xA00106)
#define Z_RATE   ((vu8*)0xA00108)
#define Z_PAN    ((vu8*)0xA0010A)
#define Z_IWAVADR ((vu8*)0xA00114)
#define Z_IWAVLEN ((vu8*)0xA00116)
#define Z_NULLADR ((vu8*)0xA00124)
static u16 rd16(vu8* p) { return p[0] | (p[1] << 8); }
static void wr16(vu8* p, u16 v) { p[0] = v; p[1] = v >> 8; }
// Blocks are absolute: b = (u32)sample->data >> 8; s, ls, le, e = b + block offsets.
// Bus: Z80_getAndRequestBus(TRUE) / Z80_releaseBus(). Only Z80 RAM is touched: the YM 0x2A latch
// (synth.c release_z80_bus) is not needed.

void note_on(...) {
    take();
    wr16(Z_WAVADR, s); wr16(Z_WAVLEN, le - s);
    *Z_RATE = rate; *Z_PAN = pan;
    *Z_STAT &= ~1;          // PLAYING returns only after the driver's copy
    *Z_LOOP |= 1;
    *Z_CMD |= 1;
    release();
    state = (ls == s) ? LOOPING : WAIT_COPY;
}

void frame_poll(void) {      // also safe from a tick handler
    if (state != WAIT_COPY) return;
    take();
    if (!(*Z_CMD & 1) && (*Z_STAT & 1)) {   // copy done, first loop recopy still ahead (table 3)
        wr16(Z_WAVADR, ls); wr16(Z_WAVLEN, le - ls);
        state = LOOPING;
    }
    release();
}

void note_off(void) {         // only for samples with a release (le < e)
    take();
    if (state == WAIT_COPY && (*Z_CMD & 1)) {   // command not taken yet: the copy is still ahead
        wr16(Z_WAVLEN, e - s); *Z_LOOP &= ~1;   // intro, loop once, release
        release(); state = RELEASE; return;
    }
    while (!(*Z_STAT & 1)) { release(); wait_us(130); take(); }   // copy in progress (≤125 µs)
    *Z_LOOP &= ~1;
    wr16(Z_IWAVLEN, e - rd16(Z_IWAVADR));
    release();
    wait_us(600);              // ≥ 4S+274 Z80 cycles of Z80 run time, bus released
    take();
    u16 a = rd16(Z_IWAVADR);
    if (a + rd16(Z_IWAVLEN) != e) {
        if (a == rd16(Z_NULLADR)) {             // stopped at le before seeing our length
            wr16(Z_WAVADR, le); wr16(Z_WAVLEN, e - le);
            *Z_STAT &= ~1; *Z_CMD |= 1;         // taken at the next $00, seamless
        } else {
            wr16(Z_IWAVLEN, e - a);             // lost or off-by-one write: outside the window now
        }
    }
    release();
    state = RELEASE;
}
```

Цена: один короткий захват шины на Note On, по одному на кадр, пока ждём копию, и два захвата плюс ожидание до 600 мкс на Note Off. Каждый захват задерживает вывод DAC на свою длину, как уже делает каждая запись YM в MDMI (`synth.c:483-503`). [В]

## 6. BlastEm

- Сборка плагина идёт с `CPU=x86_64`, без `NEW_CORE`, то есть Z80 на JIT `z80_to_x86.c` (`Makefile:233-266`, `tools/build_plugin.sh`). [И]
- BUSREQ: после запроса Z80 доходит примерно на один M-цикл, потом busack (`z80_to_x86.c:3456-3492,3538-3547`). Проверка циклов стоит только в начале инструкции (`z80_to_x86.c:335`), поэтому шина отдаётся на границе инструкции. После освобождения добавляется 1 такт (`3549-3557`). 68000 видит busack через A11100 (`genesis.c:1383-1405,1566`). [И]
- Вывод: гонка «прочитал IWAVLEN, через инструкции записал» в BlastEm есть, рваных 16-битных записей и разрыва `RES (HL)` нет. Схема с проверкой работает в обоих случаях. Случайно в `reg_test` она сработает примерно в 0,35% Note Off; чтобы проверить ветки поправки, их нужно вызывать нарочно, например Note Off в рассчитанное время. [В]
- Тайминг драйвера в BlastEm считается по тактам инструкций, задержка банка 3 такта. Для схемы нужна только последовательность событий, а её BlastEm воспроизводит. Препятствий не вижу. [В]

## 7. Только на приставке [Ж]

- Рваные 16-битные IWAVADR/IWAVLEN и разрыв RMW внутри M-цикла: проверяет ли их одна поправка на настоящей Z80.
- Реальная длина критической области в мкс (задержки банка, refresh) и хватает ли 600 мкс.
- Слышен ли сдвиг DAC от захватов шины.

## Попутно (не для 18b)

`SND_PCM_stopPlay` пишет IWAVADR/IWAVLEN = null без проверки (`snd_pcm.c:128-136`). Если захват попал в то же окно (около 0,35%), драйвер запишет поверх IWAVLEN = старое−1 и прочитает столько блоков ROM за `smp_null`: вместо тишины будет шум. Это вывод из кода, на слух не проверено. [В]
